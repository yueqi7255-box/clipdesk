# 演示视频录制

把一个系统的功能操作，做成有片头片尾、带配音、带鼠标轨迹的演示视频。

## 职责边界

## 职责范围

本 Skill 负责**从零做出一版视频**，并交付到可审片状态。

| 本 Skill 负责 | 交给下游 |
| --- | --- |
| 分析系统、设计分镜 | 文案时长类微调 |
| 撰写配音文稿 | 换外壳模板 |
| 录屏捕获（含鼠标轨迹） | 最终拼接成片 |
| 时间轴切片 | 版本管理 |
| 渲染预览 | |
| 审片后需要重录画面的改动 | |

**一句话：本 Skill 管「录」和「重录」，不管「改」和「出片」。**

## 产出契约

本 Skill 的产出必须符合下游渲染工具的数据规范：

```
<项目>/
├── project.json          ← 镜头定义
└── footage/
    ├── record.json       ← 帧时间戳 + 点击坐标
    └── frames/           ← f00000.png, f00001.png …
```

### record.json

```json
{
  "frames": [{ "idx": 0, "t": 0 }, { "idx": 1, "t": 87 }],
  "clicks": [{ "t": 4141, "x": 866, "y": 273 }],
  "duration": 142600
}
```

| 字段 | 含义 |
| --- | --- |
| `frames[].t` | 帧相对开始录制的**毫秒数** |
| `clicks[].t` | 点击事件毫秒数 |
| `clicks[].x/y` | 点击位置坐标 |
| `duration` | 录制总毫秒数 |

**`clicks` 是绘制鼠标指针涟漪的唯一依据，绝不能漏。**

### project.json

```json
{
  "id": "S01",
  "kind": "intro",
  "footage": null,
  "voice": { "text": "解说词", "duration": 3.5 },
  "duration": 3.5
}
```

本 Skill 必须填的字段：

| 字段 | 说明 |
| --- | --- |
| `shots[].id` | 镜头编号 |
| `shots[].footage` | 切片区间（片头片尾填 `null`） |
| `shots[].voice.text` | 解说词 |
| `shots[].duration` | 时长 |
| `shots[].kind` | `intro` / `outro` |
| `config.template` | 固定 `"classic"` |
| `config.stages` | 阶段划分 |
| `config.brand` | 标题文案 |

**不要手写** `voice.duration`、`currentVersion`、`versions[]`——由渲染工具生成。

## 调用渲染工具

本 Skill 不自带渲染能力。以下命令假设本机已安装配套渲染工具（clipdesk）：

```bash
RENDER_ROOT="$(cat ~/.dsh/skills/clipdesk/INSTALL_PATH 2>/dev/null)"
cd "$RENDER_ROOT"

node bin/clipdesk render "项目名"     # 渲染预览

```

**若换用其他渲染工具**：只需保证产出符合前面的「产出契约」，渲染命令按该工具的文档走。

## 禁止事项

- **禁止**自己写 ffmpeg 命令拼接视频 — 渲染交给下游渲染工具
- **禁止**自己用 PIL/Canvas 绘制顶栏字幕 — 外壳由下游渲染工具负责
- **禁止**录完直接出成片 — 必须等用户审片通过
- **禁止**手动修改 `segments/` `preview/` `versions/` 下的文件 — 那是渲染缓存与产物
- **禁止**在未确认演示环境可用前开始录制
- **禁止**用截屏替代录屏，除非视频录制确认不可用且已告知用户

# Phase 1：分析与分镜

**Exit Criteria：用户明确回复"确认""可以""开始录制"**

## 1.1 侦察环境（Scout）

**没看到的不存在。** 必须实际打开系统看真实界面，禁止凭代码猜测。

```
用 ego-browser 打开用户提供的地址
↓
截图首页
↓
识别：有哪些导航项 / 模块 / 主要操作按钮
↓
确认演示数据是否真的存在
```

记录侦察结果：

```markdown
## 环境侦察

- 地址：http://xxx
- 数据：45 名学生，6 排 × 8 列
- 主要模块：座位表、学生数据、轮换方案、轨迹查询
- 关键操作：开始排座 / 新建轮换 / 打标签
```

## 1.2 划分阶段

阶段数建议 3-5 个，对应顶栏节点图。

```
阶段名   包含镜头
初始排位  S02-S12
定期轮换  S13-S19
打标签    S20-S21
座位轨迹  S22-S23
```

## 1.3 写分镜

| 字段 | 说明 |
| --- | --- |
| 编号 | S01…Sn |
| 时长 | 秒（中文配音约 4.5 字/秒） |
| 操作 | 该镜头演示什么 |
| 文稿 | 解说词 |

**首尾必须：**

- `S01` 片头 — 一句话点题 + 价值主张
- `Sn` 片尾 — 结论式总结，不含新信息

**中间镜头**按「一步一操作」拆，每镜 2-7 秒。

## 1.4 输出待确认清单

```markdown
## 分镜设计

**结构**：片头 → 4 个阶段 → 片尾，共 24 镜头，约 1 分 45 秒
**顶栏节点图**：初始排位 → 定期轮换 → 打标签 → 座位轨迹

| 编号 | 时长 | 操作 | 文稿 |
| --- | --- | --- | --- |
| S01 | 3.5s | 片头标题页 | 班级排座系统，让排座位从半天变成几分钟。 |
| S02 | 3.0s | 打开系统首页 | 进入排座位系统，请先添加初始排位。 |
| … | | | |
| S24 | 3.8s | 片尾标题页 | 科学排座位：让结果有依据、有数据、能解释。 |

确认后我开始录制。
```

# Phase 2：录屏捕获

**Exit Criteria：帧序列 + record.json 完整落盘，帧数×间隔 ≈ 总时长**

## 2.1 视频录制（首选）

用 `ego-browser` 技能，真实操作演示。

硬性要求：

- **一次录完**，禁止分段录再拼（指针轨迹会断）
- 固定窗口尺寸 1600×900
- 操作间留 1-2 秒停顿
- 提前把所有数据准备好，避免中途等待加载

产出：

```
footage/
├── frames/          f00000.png, f00001.png …
└── record.json
```

## 2.2 record.json 格式

```json
{
  "frames": [{ "idx": 0, "t": 0 }, { "idx": 1, "t": 87 }],
  "clicks": [{ "t": 4141, "x": 866, "y": 273 }],
  "duration": 142600
}
```

| 字段 | 含义 |
| --- | --- |
| `frames[].t` | 该帧相对录制开始的**毫秒数** |
| `clicks[].t` | 点击事件毫秒数 |
| `clicks[].x/y` | 点击位置屏幕坐标 |
| `duration` | 录制总毫秒数 |

## 2.3 校验

```python
abs(len(frames) * frame_interval - duration) < 1000   # 误差 < 1 秒
len(clicks) >= 实际点击次数                            # 不能漏
```

## 2.4 截屏兜底

仅当视频录制确认不可用时：

- 逐屏截图
- 手动记录切换时刻
- **必须告知用户**：没有指针轨迹，画面不连贯

# Phase 3：切片与接入

**Exit Criteria：预览渲染成功，preview.mp4 生成**

**这一步是「剪辑」。** 把一整段连续录屏，切成 N 个镜头。

## 3.1 建项目

调用渲染工具创建项目结构（命令见 §调用渲染工具）。

若未安装渲染工具，按「产出契约」手工创建目录结构即可。

## 3.2 放入素材

把 Phase 2 的 `frames/` 与 `record.json` 复制进项目的 `footage/`。

## 3.3 切片（核心工作）

**关键理解**：切片不改动任何帧文件，只是写时间区间。

```json
{
  "id": "S03",
  "footage": { "start": 12.5, "end": 17.7 },
  "voice": { "text": "第一步，请确认教室的布局…" },
  "duration": 5.2
}
```

含义：从原始录屏的第 12.5 秒到 17.7 秒取画面，配这段解说，这一镜 5.2 秒。

**切片要点：**

- `footage.start/end` 是**录制时间轴**上的秒数
- 相邻镜头区间**不要重叠**
- 每段区间长度应 ≈ 该镜头 `duration`
- 留 0.2-0.5 秒余量，避免取到转场瞬间

## 3.4 数据契约

**必须由本 Skill 填写的字段：**

# 更改与重录

视频交付审片后，用户会提出修改意见。**所有涉及画面的改动，都回到本 Skill。**

## 入口判断

收到修改需求时先分类：

| 需求 | 走哪里 |
| --- | --- |
| 只改文案措辞 | 下游处理（改 `voice.text` 重渲） |
| 只调某段时长 | 下游处理（改 `duration` 重渲） |
| 换外壳模板 | 下游处理（改 `config.template` 重渲） |
| **画面内容要变** | **本 Skill（重录）** |
| **演示步骤缺失/顺序错** | **本 Skill（重录）** |
| **界面状态不对** | **本 Skill（重录）** |
| 用户说「重录」 | **本 Skill（重录）** |

判断不了时问用户一句：「这次是只改文案和时长，还是画面也要重录？」

## 重录规格（与首次录制完全一致）

**规格不是重录时可以放松的。** 以下每一条都必须满足，否则素材不可用：

| 规格 | 为什么不能省 |
| --- | --- |
| 视频录制，不用截屏 | 没有帧序列无法合成 |
| **一次录完，不分段拼接** | 分段录会导致 `clicks` 坐标错位、指针轨迹断裂 |
| 窗口固定 1600×900 | 尺寸变化会导致画面缩放不一致 |
| **保留点击事件** | `record.json` 的 `clicks` 是绘制指针涟漪的唯一依据 |
| 操作间留 1-2 秒停顿 | 否则切片时容易取到转场瞬间 |
| 沿用原项目的外壳模板 | 换模板会让重录的镜头与其余镜头不一致 |

**最容易犯的错**：只重录了画面，忘记采集 `clicks`，导致重录的那个镜头没有指针效果，和其余镜头风格不一致。

## 执行流程

### 1. 定位现状

```bash
cat "<项目路径>/project.json"
```

确认：

- 哪些镜头要重录（用户意见里提到的 `shotId`）
- 原项目的 `config.template`、`config.size`、`config.fps`
- 现有 `footage/record.json` 的结构

### 2. 重新录制

按 Phase 2 的完整规格执行，**只录需要改的部分**：

- 如果只是某个镜头的画面不对 → 只录那一段操作
- 如果整体流程都变了 → 整片重录

### 3. 合并素材

**这是重录最容易出错的一步。** 两种方式：

**方式 A：追加到原帧序列**（推荐，保留其他镜头）

```
原 frames/ 已有 f00000 ~ f01630
新录的帧追加为 f01631 ~ f01800
原 record.json 的 frames 数组追加对应时间戳（偏移 = 原时长）
clicks 数组同样追加，坐标不变
```

要点：

- 新帧的时间戳必须**接在原时长之后**
- `duration` 更新为新的总时长
- **不要覆盖原有的 clicks**

**方式 B：全部重录**（简单可靠，但耗时）

直接替换整个 `footage/`，所有镜头重新切片。

**选择建议**：改 1-3 个镜头用 A；改 4 个以上或流程大改用 B。

### 4. 更新切片

只改受影响镜头的 `footage.start/end`，其余镜头保持不动。

```json
{
  "id": "S14",
  "footage": { "start": 62.3, "end": 69.5 },   ← 指向新录素材
  "voice": { "text": "…", "duration": 7.2 },
  "duration": 7.2
}
```

### 5. 校验

```python
# 帧数与时长匹配
abs(len(frames) * interval - duration) < 1000

# clicks 数量 = 实际点击次数（重录部分）
len(new_clicks) >= 本次点击次数

# 切片区间无重叠、不越界
for shot in shots:
    assert shot.footage.end <= duration
```

### 6. 渲染并交回

按 §调用渲染工具 渲染，然后启动服务，告诉用户：

```
重录完成，已更新 X 个镜头。请再审：http://127.0.0.1:4300/
```

**后续的文案时长类修改，交给下游渲染/审片工具处理。**

## 重录检查清单

- [ ] 确认了哪些镜头需要重录

# 常见故障

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 片头片尾空白或出现顶栏 | `kind` 未写入，或 `footage` 不为 `null` | 检查 `shots[].kind`，指纹会因 `kind` 变化自动重渲 |
| 指针不显示 | `clicks[].t` 不在该镜头 `footage` 区间内 | 核对切片区间 |
| 顶栏节点图不高亮 | `stages[].ids` 缺该镜头 | 补全 |
| 配音与画面错位 | `duration` 与 `footage` 区间长度差太多 | 调整 `duration` 或区间 |
| 读取素材极慢 | 项目在 iCloud/网盘目录 | 移到本地磁盘 |
| 渲染提示"暂无录屏素材" | `footage.start/end` 为空或帧缺失 | 检查切片与 `frames/` |
